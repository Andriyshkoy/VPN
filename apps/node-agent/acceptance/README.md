# Приёмка node-agent

`live_check.py` по умолчанию только показывает план. Сетевые вызовы и новые
доступы появляются исключительно с `--execute` после развёртывания API.

```sh
python3 acceptance/live_check.py --execute \
  --tokens-file private/operator-tokens.json --restart-api
```

Токены берутся из приватного файла установщика: `operator_token` имеет три
scope, `readonly_token` — только `access:read`. В аргументах процессов,
обычном stdout и публичной квитанции токены и профили не печатаются.

Сценарий создаёт по одному доступу Hysteria/REALITY с уникальным `owner_ref`,
проверяет повторяемую выдачу и конфликт ключа, разделение scope, экспорт,
отсутствие URI в обычных метаданных, приостановку/возобновление/отзыв.
Изменение квоты 1 → 2 ГиБ проверяется повторяемым PATCH с сохранением профиля.
Hysteria проверяется до активации и после первого настоящего подключения.
Запись даты активации делает существующий collector раз в минуту; после
настоящего трафика проверка ждёт до 90 секунд, опрашивая только API.
Это задержка наблюдения состояния, а не точные часы продуктового биллинга.
Флаг `--restart-api` разрешает один перезапуск только новой службы
`vpn-control-api.service` для проверки долговечной идемпотентности.

Из российского стенда каждый этап запускает свежие официальные HY2/Xray
клиенты. В положительных случаях проверяются HTTPS, NL exit и содержимое
example.com; при блокировке/отзыве проверяется отказ новых запросов.
Судьба ранее открытых соединений и режим TUN телефона этим не проверяются.

В `finally` отзываются только собственные canary-доступы, останавливаются
только собственные RU units, собираются приватные логи и удаляется собственный
каталог. Проверяются свободные порты, сохранность routes/DNS во время каждой
пробы, а также хеши прежних Hysteria/Marzban пользователей, конфигов и PID.
Любая неудачная очистка остаётся ошибкой в квитанции и требует разбора;
чужие записи и firewall автоматически не исправляются.

Публичный результат: `acceptance/live-result.json`. Детальные ответы API,
секретные профили и stderr лежат в игнорируемом `private/acceptance-*` (`0700`,
файлы `0600`).

Если полный запуск уже доказал scope, идемпотентность, PATCH и переживание
перезапуска API, оставшийся жизненный цикл можно проверить отдельно без
повторного перезапуска:

```sh
python3 acceptance/lifecycle_check.py --execute \
  --tokens-file private/operator-tokens.json --activation-wait-seconds 90
```

Этот сценарий создаёт два новых собственных доступа, ждёт наблюдения
активации Hysteria, затем проверяет suspend → resume с прежним профилем →
revoke свежими клиентами. Результат — `acceptance/lifecycle-result.json`,
приватные доказательства — `private/lifecycle-*`. Исторические неудачные
квитанции сохраняются отдельно и не переписываются в успешные.

Флаг `--diagnostic` выполняет оставшийся жизненный цикл без повторения уже
доказанной активации: отдельно записывает example.com, Cloudflare trace с
проверкой NL exit и ipify. Неудачная положительная проба сохраняется; допускается
одна новая попытка подключения с отдельным результатом. После отзыва проверяются
отказ новых запросов и отсутствие собственных записей в обеих backend-базах.
Квитанция этого отдельного запуска — `acceptance/live-lifecycle-diagnostic.json`.
Cloudflare IP сравнивается через `ipaddress` с точными адресами, подтверждёнными
read-only HTTPS-запросами с NL по IPv4/IPv6 и адресами интерфейсов; выбор IPv6
прокси-сервером сам по себе не считается сбоем. Наличие повторного подключения
сохраняет общий FAIL, даже если повторная проба восстановила передачу данных.

## Результат приёмки 2026-11-09

Комбинированная квитанция — `acceptance/live-completion.json`. Она связывает
28 успешных проверок control plane из предыдущего полного запуска (scope,
идемпотентность, PATCH, сохранение после перезапуска API), отдельное наблюдение
активации collector через 11,9 секунды и финальный цикл на release
`7beb8df7046597044168`. Локальный полный набор перед этим релизом: 94/94 теста.

Финальный цикл прошёл 25/25 проверок: оба протокола передавали HTTPS к трём
целям до suspend и после resume с прежними URI, с первой попытки без reconnect.
Suspend и revoke запрещали свежие подключения; после revoke обе backend-записи
отсутствовали, оставались API tombstones, повторный revoke был безопасен.
Старые 12 Hysteria-доступов, 6 VLESS-профилей, конфиги и PID сохранены;
собственные canary-доступы отозваны, RU units/каталоги удалены, порты освобождены.

Реверсивные suspend/update теперь запрещают новую авторизацию без `/kick`;
завершение ранее открытых потоков не гарантируется. Это устраняет найденный
sticky kick: офлайн-пользователь раньше получал отложенный разрыв первого
потока после resume. Старые неудачные квитанции, включая преждевременную
проверку активации и воспроизведение sticky kick, сохранены с исходным FAIL.
Исходный `live-result.json` не объявляется успешным. Эта приёмка проверяет
нативные SOCKS-пути из RU, а не мобильный TUN, нагрузку или длительное видео.
