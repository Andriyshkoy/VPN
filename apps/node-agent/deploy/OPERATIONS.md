# Развёртывание агента узла NL

Это агент управления транспортами одного узла. Его SQLite хранит локальные
доступы и операции API. Центральные пользователи, тарифы, платежи и ledger
должны находиться в отдельном backend, а не в этой базе.

## Установка

Перед установкой должны пройти тесты приложения и обоих адаптеров.
`requirements.lock` содержит закреплённые runtime-зависимости. Проверка
пакета без изменений удалённого сервера:

```sh
python3 deploy/install.py
```

Первое развёртывание и дальнейшее обновление только агента:

```sh
python3 deploy/install.py --execute
```

Установщик проверяет NL-адрес и hostname, создаёт отдельного системного
пользователя `vpn-control`, устанавливает зависимости в venv нового release
и переключает `current` атомарно. Он управляет только своими API, Hysteria bridge
и backup units. Обновление Hysteria/Xray, firewall, маршрутов, DNS, Caddy,
бота и центрального backend не выполняется.

При обновлении перед переключением создаётся копия локальной базы.
Если запуск не прошёл readiness, старые release и unit-файлы возвращаются.
После неудачной первой установки база и приватная конфигурация сохраняются
для диагностики и повторной установки. В случае SSH timeout сначала проверить
состояние собственных units, а не запускать установку повторно вслепую.

## Размещение

| Назначение | Путь |
| --- | --- |
| Release | `/opt/vpn-control/releases/<bundle-sha-prefix>/` |
| Текущий release | `/opt/vpn-control/current` |
| Код и venv | `/opt/vpn-control/app`, `/opt/vpn-control/venv` |
| API | `127.0.0.1:18010` |
| Метаданные узла | `/var/lib/vpn-control/control.sqlite3` |
| Каталог хешей токенов | `/etc/vpn-control/tokens.json` |
| Копия открытого Hysteria-сертификата | `/etc/vpn-control/hysteria-peer.crt` |
| Bridge socket | `/run/vpn-control-hys/bridge.sock` |
| Квитанция установки | `/opt/vpn-control/deploy.json` |
| Копии метаданных | `/var/backups/vpn-control/` |

Исходный bearer оператора создаётся локально в `private/operator-token.txt`,
а отдельный токен только для чтения — в `private/readonly-token.txt`.
Их bundle `private/operator-tokens.json` содержит `operator_token` и
`readonly_token`; все три файла имеют права `0600`. На сервер сохраняются
только SHA256 в каталоге токенов.
Каталог хешей и существующие Marzban credentials передаются приложению через
`LoadCredential`; исходные секреты Marzban не становятся общедоступными.
Для замены токена необходима отдельная явная операция, обычный повторный
deploy существующий каталог токенов не меняет.

API работает непривилегированным пользователем. Привилегированный Hysteria
bridge принимает только ограниченный набор JSON-операций от разрешённого
Unix peer UID и обслуживает только собственное пространство имён доступов.
Произвольные команды, пути, SSH и sudo через этот протокол не исполняются.

У bridge нет DAC capabilities и доступа к закрытому TLS-ключу Hysteria.
Установщик копирует только открытый сертификат в root-owned файл `0600`
и сравнивает SHA256 leaf DER с исходным сертификатом. Это позволяет bridge
читать сертификат без ослабления прав исходного файла другого системного UID.
При ротации серверного сертификата нужно повторить deploy агента, чтобы
обновить его публичную копию и pin новых профилей.

## Проверка

```sh
systemctl status vpn-control-api.service vpn-control-hys.service
systemctl status vpn-control-backup.timer
curl --fail http://127.0.0.1:18010/healthz
```

`/healthz` проверяет только жизнь процесса. `/readyz`, каталог сервисов,
OpenAPI и операции требуют bearer с соответствующими scopes. Readiness
проверяет реальную доступность backend-адаптеров.

Для доступа из рабочего окружения использовать SSH-туннель:

```sh
ssh -i ~/.ssh/id_ed25519_codex -N -L 18010:127.0.0.1:18010 root@195.133.195.40
```

Публичный порт или HTTPS-маршрут для этого API не создаётся. Будущему
центральному backend потребуется отдельный защищённый канал к агенту.

## Копии и восстановление

Таймер создаёт копию ежедневно после `04:00 UTC` с задержкой до 15 минут.
SQLite копируется через online backup API, включая актуальные WAL-данные.
В архив входят база агента, каталог хешей токенов, `node.env`, открытая копия
`hysteria-peer.crt` и deployment metadata;
plain bearer и клиентские профили в архив не добавляются. Архивы `0600`,
каталог `0700`; хранятся 14 дней и как минимум две последние копии.

```sh
python3 /opt/vpn-control/app/deploy/backup.py create
python3 /opt/vpn-control/app/deploy/backup.py verify /var/backups/vpn-control/АРХИВ.tar.gz
python3 /opt/vpn-control/app/deploy/backup.py verify /var/backups/vpn-control/АРХИВ.tar.gz --extract-to /root/НОВЫЙ-каталог
```

Извлечение не заменяет работающую БД. Для восстановления остановить только
`vpn-control-api.service`, сохранить текущую БД с WAL/SHM и каталог токенов,
проверить архив, затем установить самостоятельную SQLite-копию с владельцем
`vpn-control:vpn-control` и правами `0600`. Старые WAL/SHM не смешивать с
восстановленной БД. Каталог токенов восстанавливать root:root `0600`.
После запуска проверить readiness и реальные доступы.

Копия агента **не включает базы Marzban и Hysteria/Mongo**. Их восстановление
и соответствие локальным access IDs требуют отдельных согласованных копий.
Откат базы агента без сверки backend может потерять сведения о созданных позже
доступах; автоматически удалять такие backend-доступы нельзя.
