# Подготовленный переход на два тарифа

Статус: локальная подготовка, без выкладки. Эта ветка не меняет рабочие
сервисы, настройки списаний или данные пользователей и не отправляет рассылки.

## Принятые правила

| Тариф | Почасовая цена за аккаунт | За 720 часов | Доступ |
| --- | ---: | ---: | --- |
| Basic | 0,07 ₽ | 50,40 ₽ | Hysteria, один одновременно подключённый клиент |
| Plus | 0,14 ₽ | 100,80 ₽ | Hysteria и VLESS/REALITY, без лимита устройств |

50/100 ₽ — округлённые месячные ориентиры. Сохраняются существующие почасовой
движок, учётные периоды, журнал операций и защита от повторного списания.
Технические ключи одного тарифа не становятся отдельными платными единицами.
Выпуск и замена новых ключей бесплатны; исторические операции не переписываются.
Автосписания остаются выключенными до отдельного решения владельца.

Режим бесконечного баланса — ручной флаг в админке. Он показывает `∞` и
отключает расходование денег, сохраняя реальный конечный остаток и историю.
Миграция не включает его никому, включая владельца и ранее обсуждавшиеся
аккаунты. Ручное исключение из бизнес-аналитики — отдельный флаг.

- [Сборка Hysteria с ограничением одновременных клиентов](../engines/hysteria/README.md).

Ограничение Basic считает QUIC-соединения с одним ключом в одном процессе
Hysteria. Внутри соединения допустимы многие потоки. Это не привязка к железу
и не распределённый лимит между несколькими серверами. Неразличимый обрыв сети
освобождает слот после обнаружения разрыва QUIC, а не мгновенно.
Неподдерживаемый сервер должен отказывать в выпуске ограниченного ключа.

Hysteria выдаётся для Hiddify как JSON-профиль с проверкой отпечатка сертификата;
VLESS остаётся ссылкой `vless://`. Настоящий Hiddify 5.5.5 подтвердил подключение
с верным отпечатком и отказ с неверным. Обычная Hysteria URI с `pinSHA256`
не подходит для этого клиентского сценария: его парсер игнорирует параметр.
Сертификаты и действующие ключи сервера сохраняются.

Рассылки создаются как черновики. Запуск требует предпросмотра точного состава
получателей и отдельного подтверждения в админке. Неопределённый результат
отправки не повторяется автоматически: Telegram не предоставляет ключа
идемпотентности отправленного сообщения.

## Проверки перед будущей выкладкой

Это порядок будущей отдельной операции, а не команда запускать её сейчас.

1. Зафиксировать проверенные версии кода и контрольные суммы артефактов.
   Сохранить резервные копии БД, конфигурации узла и прежних бинарников.
2. Оставить биллинг выключенным. Проверить на отдельном стенде обновлённые
   runtime, node-agent и Hysteria: фактические capabilities, первый и второй
   клиенты Basic, многопоточность первого, повторное подключение, отзыв ключа,
   Plus и переключение тарифов. Одного HTTP 200 недостаточно.
3. Проверить обновление схемы `g5c9d2e3f4a5` → `h6d0e3f4a5b6` и финансовые
   инварианты на копии данных. Alembic добавляет схему, не назначает тарифы.
4. Получить свежий предпросмотр назначения тарифов: один активный конфиг →
   Basic, два и более → Plus; полностью приостановленным доступ не включать.
   Проверить снимок непосредственно перед применением. Не назначать `∞`.
   После проверки нового узла отдельно включить существующий NL в размещение.
   Старый KZ перестать использовать для новых размещений, сохранив его Manager
   доступным для отзыва прежних ключей.
5. Отдельно проверить завершение перехода старых ключей и получение новых
   ключей через бота. Включение списаний возможно лишь после проверки
   полноценного управления доступом, включая паузу и недостаток средств.
6. Выполнить ручной smoke в России на обоих тарифах и поддерживаемых клиентах.
   Подготовить текст уведомления. Рассылать и включать списания — только после
   отдельного решения владельца.

Автоматическая миграция при старте приложения, включение биллинга и отправка
уведомлений не входят в подготовку этой ветки. Производственные IaC-пины
сохраняются; кандидат должен выбираться явно.

## Локальная проверка 9 ноября 2026

- Backend: **808 тестов прошли**, включая PostgreSQL-конкурентность списаний,
  ручного `∞`, изменений тарифа и запусков рассылки. Для тестов использован
  отдельный локальный PostgreSQL 16.15, без данных пользователей.
- Переход заполненной схемы g5 → h6 сохранил старые строки кошельков, ledger,
  конфигов и почасовых запусков. Пустая БД прошла все миграции до h6 и
  `alembic check` без расхождений.
- Frontend: **41 тест**, lint и сборка прошли; 11 кадров DEMO сняты с
  синтетическим API, внешние запросы запрещены.
- Node-agent: **140 тестов**, runtime: **92 теста**. Проверена реальная цепочка
  Mongo → HTTP-авторизация → native QUIC, включая гонки, потерю связи и отзыв
  ключа; изменённые Go-пакеты прошли `-race`.
- IaC: **142 теста**, ещё **28 тестов** чистого стенда; синтаксис и lint прошли.
- Руководства: проверены 9 Markdown-файлов, 6 платформ, 7 официальных источников
  иллюстраций и 17 настоящих изображений в приватном preview с контрольными суммами.

Для продукта используется полный путь выкладки шести образов: bot canary,
активация admin hub и promotion. Старый IaC-путь обновления только четырёх
Python-образов не обновляет интерфейс и не подходит для этой версии продукта.
Необязательная отдельная публикация образов не означает, что canary переиспользует
её дайджесты: его собственный release manifest определяет устанавливаемые образы.

Сборки контейнеров, их запуск и smoke из России проверяются для конкретного
кандидата отдельно. Актуальная квитанция готовности связывает исходники,
артефакты и фактические результаты. Локальные DEMO и QUIC-тесты не подтверждают
стабильность всех операторских сетей или работу мобильных белых списков.
